# ibmmq-jms-guide — COA/COD delivery reports with Micronaut 4 + IBM MQ (JMS 2.0)

Production-ready example project demonstrating IBM MQ **COA (Confirmation On Arrival)
and COD (Confirmation On Delivery) delivery reports** using the **javax.jms / JMS 2.0**
client (`com.ibm.mq.allclient`) under **Micronaut 4** (for DI /
`@ConfigurationProperties` / `@Factory` / lifecycle only — JMS is managed manually
via `JMSContext`).

## Concept (summary)

- The **producer** sends a persistent business message to the business queue, setting
  `JMSReplyTo` = report queue and enabling COA+COD via the JMS properties
  `JMS_IBM_Report_COA` / `JMS_IBM_Report_COD`.
- The **COA** is generated by the queue manager when the message *arrives* on the destination queue.
- The **COD** is generated when the consuming application performs a *destructive get* (and commits).
- The **report consumer** reads the report queue, reads the feedback code via
  `JMS_IBM_Feedback` (259=COA, 260=COD, 258=EXPIRATION, 275=PAN, 276=NAN; other `MQRC_*`
  reason codes = exception) and correlates `JMSCorrelationID` -> original `MessageId` (default
  `MQRO_COPY_MSG_ID_TO_CORREL_ID`).

## Spin up a local broker (docker-compose)

`docker-compose.yml` brings up the broker **and** a Postgres primary/replica pair (read/write split
from issue #40): `postgres-primary` (writer, 5432) + `postgres-replica` (hot-standby via streaming
replication, 5433).

```bash
docker compose up -d
docker compose logs -f mq                  # wait for "Started queue manager"
docker compose logs -f postgres-replica    # wait for "started streaming WAL from primary"
# Web console: https://localhost:9443/ibmmq/console
docker compose down              # 'down -v' also discards the data volumes
```

The files `mqsc/10-channel-auth.mqsc` and `mqsc/20-queues.mqsc` are mounted under `/etc/mqm` and
applied at queue-manager creation (a **production** setup with `APP.*` objects, CONNAUTH and CHLAUTH).
The **IT**, for reliability, uses the image-default `DEV.*` objects (user `app`
pre-authorized to `DEV.**`).

## Delivery-report persistence with a read/write split (issue #40, ADR-0005)

Every COA/COD report is persisted into an append-only **`delivery_report`** audit table via Micronaut
Data JDBC, against an Aurora-like writer/reader connection split: the `default` (writer/primary)
datasource receives the idempotent `INSERT`s (`ON CONFLICT DO NOTHING`, `UNIQUE(correlation_id,
feedback)`) and the `reader` (replica) datasource serves the read-model queries. Persistence is
best-effort (it never breaks reconciliation on the already-acked path). Operational details, pool sizing,
and the tests (`DeliveryReportPersistenceIT` in `verify`; `DeliveryReportReplicationIT` opt-in via
`-Preplication`) are documented in **`docs/runbook.md` §2.5**.

```bash
# Point the app at the split (override application.yml):
-Ddatasources.default.url=jdbc:postgresql://localhost:5432/correlation   # writer
-Ddatasources.reader.url=jdbc:postgresql://localhost:5433/correlation    # reader/replica
# username/password: corr / corrpass
```

## Gated COA/COD demo (one command, against the local broker)

`CoaCodDemoRunner` is a runner **gated behind an EXPLICIT flag** (`demo.coa-cod.enabled=true`,
NEVER on during normal startup). Activated via the Micronaut `demo` profile, it runs at startup,
reuses the production beans (producer / consumer / report consumer + the narrated logger) and runs the
full **produce -> consume -> COA/COD** flow exactly once, printing the narrated stages
(`[stage=PRODUCE/CONSUME/COMMIT/CLASSIFY/CORRELATE/COA/COD/RECONCILE]`) and a final
`[resultado=PASS|FAIL]` summary that validates **feedback 259 (COA) + 260 (COD)** and **`correlId == messageId`**.

Prerequisite: the local broker up (`docker compose up -d`, with `MQ_ADMIN_PASSWORD` set). The `demo`
profile connects as **admin / `DEV.ADMIN.SVRCONN`** because the queue manager's report PUT *passes* the
original message's identity context, so it needs the full context authority (`+passid` —
`PASSID/PASSALL/SETID/SETALL`), which only a privileged principal holds. The low-privilege `app` user
lacks `+passid` (`+setall` alone is insufficient) and would fail with `MQRC_NOT_AUTHORIZED (2035)`,
dead-lettering the report (the report queue would stay empty). See `docs/runbook.md` §2.2 / §7.1.

```bash
docker compose up -d                 # prerequisite: broker up (wait for "Started queue manager")

# IMPORTANT: micronaut.environments must reach the FORKED app JVM (mn:run forks its own JVM).
# A "bare" -D on the Maven CLI configures the Maven JVM, NOT the app's — so the environment
# and native-access go INSIDE -Dmn.jvmArgs. (Equivalent alternative: export the environment
# variable MICRONAUT_ENVIRONMENTS=demo before the command.)
JAVA_HOME=/home/rodrigo/.local/jdk25 /home/rodrigo/.local/maven-current/bin/mvn mn:run \
  -Dmn.jvmArgs="--enable-native-access=ALL-UNNAMED -Dmicronaut.environments=demo"
```

The `demo` profile (`src/main/resources/application-demo.yml`) sets `demo.coa-cod.enabled=true` and applies
the admin overrides. Without the `demo` environment active, the flag is absent, the runner bean is
**not instantiated** (`@Requires`) and normal startup is unaffected.

## Note on Corretto 25: `--enable-native-access`

The IBM MQ client loads native libraries via `System.loadLibrary`. On Java 25 this emits a
*native-access* warning. That is why `surefire` and `failsafe` pass:

```
--enable-native-access=ALL-UNNAMED
```

When **running the application** directly, add the same argument to the JVM:

```bash
JAVA_HOME=/home/rodrigo/.local/jdk25 /home/rodrigo/.local/maven-current/bin/mvn mn:run \
  -Dmn.appArgs="" -Dmn.jvmArgs="--enable-native-access=ALL-UNNAMED"
```

## Layout

```
config/        MqProperties (@ConfigurationProperties) + MqConnectionFactoryFactory (@Factory, pool)
producer/      BusinessMessageProducer (sends with COA+COD)
consumer/      BusinessMessageConsumer (destructive get -> COD) + ReportMessageConsumer (reads reports)
correlation/   CorrelationStore + InMemory + persistent skeleton
report/        ReportFeedbackRouter (pure feedback -> ReportType mapping)
model/         DeliveryEvent, PendingMessage, ReportType
mqsc/          production objects (channel/auth + queues/DLQ/backout)
```
