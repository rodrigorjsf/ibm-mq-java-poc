# ibm-mq-java-poc — documentation hub

Production-grade reference for integrating **Java 25 / Micronaut 4** with **IBM MQ** via
**Jakarta Messaging 3.0 (`jakarta.jms`)**, with deep focus on **COA / COD delivery reports**
(Confirmation On Arrival / Confirmation On Delivery) in a distributed, Kubernetes-hosted,
competing-consumer topology at ~10,000 rpm.

**What this repository ships:**

- A **runnable Micronaut module** (`ibmmq-jms-guide/`) with unit tests and a live Testcontainers
  integration test (COA + COD end-to-end against a real broker).
- A **local k3s distributed harness** (`deploy/k3s/` + root `Makefile`) — IBM MQ + Postgres +
  publisher / competing-consumer microservices on a k3s-in-Docker cluster, with a shared
  JDBC correlation store and a load-test profile.
- An **exhaustive technical guide** (`docs/guide-ibmmq-jms-micronaut.md`) and a
  **standalone bilingual HTML** (`docs/index.html`) generated from it.
- **Validated research** (`research-output/`) — bytecode-verified fact sheets and the findings
  that the implementation is built on.
- **AI assets** (`ai/`) — a reusable, project-agnostic COA/COD review skill.

> `com.ibm.mq:com.ibm.mq.allclient:9.4.5.0` (the `javax.jms` / JMS 2.0 client) and
> `org.messaginghub:pooled-jms:2.0.9`. The namespace flip is documented in
> [ADR-0012](docs/adr/0012-jakarta-messaging-primary-namespace.md) (decision, rationale,

> — not purged.

Micronaut is used only for dependency injection, configuration, and lifecycle.
`JMSContext` is managed by hand to retain full control over COA/COD report options.

## Entry points

### k3s distributed harness (root `Makefile`)

Requires: Docker, `kubectl`, `k3d` (see `make doctor`). Provisions a full k3s-in-Docker cluster
with IBM MQ, Postgres, and three competing-consumer microservice roles.

```bash
make doctor       # check required tooling
make up           # provision + initialize the whole k3d harness (build → import → deploy → wait)
make verify       # show AC1/AC2 evidence: competing consumers, DLQ depth, reconciliation
make console      # port-forward the IBM MQ web console (https://localhost:9443/ibmmq/console)
make logs         # follow narrated logs across all harness roles
make down         # tear down the k3d cluster
make load         # sustained-load run (bounded N, then settle) — ADR-0007
make load-verify  # assert the load run results (exit non-zero on breach)
make compose-up   # single-broker dev env (docker compose, no k3s)
```

### Runnable module (`ibmmq-jms-guide/`)

Requires: JDK 25+ (Amazon Corretto 25), Maven 3.9+, Docker (for the integration test).

```bash
cd ibmmq-jms-guide

# Unit tests (no broker needed)
mvn test

# Full end-to-end: spins up IBM MQ via Testcontainers and verifies COA + COD
mvn verify

# Opt-in profiles (slow / resource-intensive, excluded from the default gate)
mvn verify -Preplication   # physical Postgres replication IT
mvn verify -Pscenarios     # expiration / reconnect / pool-invalidation scenarios
mvn verify -Pvt            # virtual-threads evidence IT
```

On JDK 25 the MQ client needs `--enable-native-access=ALL-UNNAMED` (already wired into the
Surefire/Failsafe `argLine`).

## COA/COD in brief

A producer sends a persistent `TextMessage` requesting **COA** (confirm on arrival) and **COD**
(confirm on delivery), with `JMSReplyTo` pointing at a dedicated report queue. IBM MQ generates
the report messages and PUTs them onto that queue. A business consumer destructively reads the
business message (triggering COD); a report consumer reads the report queue, branches on the
**feedback code** (`MQFB_COA = 259`, `MQFB_COD = 260` — from `com.ibm.mq.constants.MQConstants`),
and correlates `report.JMSCorrelationID → original MessageId` (default
`MQRO_COPY_MSG_ID_TO_CORREL_ID`). In the distributed harness, the shared Postgres
`pending_message` table makes this reconciliation cluster-wide across competing-consumer pods.

## Gotchas (full detail: the guide §5 and `CLAUDE.md`)

- **Report-PUT authority (MQRC 2035):** the Queue Manager does a PUT-with-context to deliver
  the COA/COD report. The authority it requires is **`+passid`** — `+setall` alone is
  insufficient. Grant `SET AUTHREC ... AUTHADD(PUT, PASSID, PASSALL, SETID, SETALL)` on the
  report queue. Without it the report silently lands on the DLQ (verified live on k3d).
- **Report persistence** is inherited from the original message — it is *not* non-persistent
  by default.
- **Testcontainers + modern Docker:** use Testcontainers 2.x; pin `commons-codec:1.16.1` (the
  zerodep transport references a class removed in 1.17+).
- **Jakarta namespace:** this project now ships `jakarta.jms` (Jakarta Messaging 3.0,
  ADR-0012). If your environment still uses `javax.jms` (JMS 2.0), see the migration pointer
  in the [Stack](#stack) section above and ADR-0012 for the full delta.
